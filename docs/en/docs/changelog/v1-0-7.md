**v1.0.7’s main goal: performance testing core engine rework** — *engine abstraction* and the *self-developed bench*. This was the release that introduced the pluggable engine model used ever since.

## Main Capabilities

### Self-developed bench (the benchscope engine)

- Implements a self-developed testing engine based on the **vLLM / SGLang bench approach**.
- **No dependency on a local framework environment** — install with `pip` and test OpenAI-compatible services **remotely**.

```bash
pip install benchscope
benchscope perf --model Qwen2.5-7B --base-url http://127.0.0.1:8000
```

### Versioned engines

- Supports **native bench for specific versions** of vLLM (for example `vllm-0.23`) and SGLang (for example `sglang-0.5.10`).

### Parameter dropdowns + descriptions

- Engine parameters are set **independently**, chosen from **dropdowns**, and show **descriptions**.

### Settings → Bench config bar

- Built-in **`benchscope`** / **`vllm-0.23`** / **`sglang-0.5.10`**, with introductions and comparisons.
- A **per-engine Mock switch** — the beginning of the panelized Settings introduced here.

See [Settings → Bench Engines](../core/settings.md).

## Environment Validation Convention (Mandatory)

- **Native engines (vllm / sglang)** — the installed versions of `torch` and `vllm` / `sglang` **must be validated**; if not satisfied, proceeding to the next step is **blocked**.
- **The self-developed bench** — no such environment is needed; a local installation can test **remote APIs**.

::: warning
When you rely on a native vLLM / SGLang engine, make sure the matching framework version is installed in the environment, or the task will be blocked by environment validation.
:::
