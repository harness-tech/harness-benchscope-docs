# v1.1.1 发布说明

**发布日期**：2026-09-05
**变更类型**：patch（按用户指示特殊处理推送 PyPI）

## 版本概述

v1.1.1 为 v1.1.0（性能实时面板 / 单请求快照 / Dashboard Overview 重构 / Sessions 体验）发布后的**修复版本**，聚焦安装包完整性与配置健壮性：`pip install` 后 Settings 各栏有内容、历史 Provider 可正常编辑、PyPI 页面图片正常显示。

## 更新内容

### 修复：安装包 Settings 空内容

现随包分发 `benchscope/configs/*.yaml`（models / datasets / benchs 等 9 个配置文件）与内置技能目录——`pip install` 后 **Settings 的 Models / Datasets / Bench Engines / Skills 各栏均有条目**（不再依赖源码目录）。

### 修复：Provider 缺失 id

历史遗留的 Provider（如旧版「Default」，由仅含 `api` 字段的老配置迁移而来）可能缺少 `id` 字段，导致性能创建任务时无法选择该 Provider、Settings 编辑报「未知 Provider: undefined」。现在配置加载时会**自动回填缺失的稳定 id**（由名称 slug 生成，如 Default → `provider_default`，冲突时追加数字后缀保证唯一），并同步持久化；`active_provider` 缺失 / 失效时回退到首个有效 id。

### 修复：PyPI 图片显示

README 主截图更换为 `benchscope-performance.png`；logo 与主截图的图片引用改为 **GitHub raw 绝对 URL**（`https://raw.githubusercontent.com/...`），使 PyPI 页面也能正常渲染图片（此前相对路径在 PyPI 无法解析）。

### 技能迁入包内

内置技能目录由仓库根 `skills/` 迁入包内 `benchscope/skills/` 并作为 package-data 分发；`api_skills` 的路径解析同步更新，**开发与安装后路径一致**（Settings → Skills 在两种环境下行为相同）。

## 验证要点

- 重建 wheel / sdist：均包含 `benchscope/configs/*.yaml`（9 个）与 `benchscope/skills/**/*`（30 个文件）。
- `GET /api/config/model-catalog` = 2 组、`GET /api/config/datasets` = 12 个、`GET /api/benchs` = 5 个引擎（benchscope / vllm-0.23 / sglang-0.5.10 / native-hf / mock）、`GET /api/skills` = 3 个技能。
- 构造含无 id Default 的旧 settings.json → 加载后 `list_providers()` 返回 `id=provider_default` 且已持久化，编辑成功。

## 升级提示

- 从 v1.1.0 升级：直接 `pip install --upgrade benchscope`，无需数据迁移；若曾手工修改 `skills/` 目录，请知悉其已迁移至包内 `benchscope/skills/`。
- 历史 Provider 的 id 回填在**首次启动**时自动完成，Settings 中即可正常编辑。
