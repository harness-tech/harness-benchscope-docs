# 导入导出与备份

Datas 支持对性能记录做**备份**（导出 zip）、**导入**（从 zip 恢复）、**分享**（导出 PNG 图片），用于在不同机器 / 环境间迁移历史记录，或将结果以图片形式分享。

## 1. 功能说明

| 功能 | 入口 | 产物 / 行为 | 方向 |
| --- | --- | --- | --- |
| 备份 | 详情第 1 行**备份**按钮 | 下载 `{run_id}.zip`（运行目录 + 终端日志） | 导出 |
| 导入 | 左侧列表**导入**按钮 → 抽屉 | 从 zip 恢复一条记录到本地 | 恢复 |
| 分享 | 详情第 1 行**分享**按钮 | 下载 `{run_id}.png`（详情整页截图） | 导出 |

<div class="info">

**info**：

备份 / 导入针对**性能记录**（`kind=perf`），产物为扁平 zip。精度评测产物（`evals/`）随数据目录整体迁移，不在本处导入导出。

</div>

## 2. 页面结构

```
左侧列表标题栏：  [ 导入(上传图标) ]  [ 刷新(循环图标) ]

详情第 1 行标题栏：  <run_id>   [ 删除 ] [ 备份 ] [ 分享 ]

导入抽屉（右侧 360px）：
┌──────────────────────────┐
│  导入 record               │
│  导入提示(importTip)        │
│  [ 上传 zip 包 ]            │
│  进度条（上传中）            │
│  结果：导入成功 / 已存在 / 失败│
│  [ 取消 ]                   │
└──────────────────────────┘
```

## 3. 输入参数与字段限制

| 字段 | 类型 | 限制 / 约束 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `file`（导入） | file | 必填，仅 `.zip`；`multipart/form-data`，字段名 `file` | — | 备份 zip；非 zip 直接拒绝 |
| zip 内容 | — | 须为**扁平**文件（无子目录，防 zip-slip） | — | 至少含 `run.json` |
| `run.json` | json | 必填；含 `run_id`、`kind`（perf / eval） | — | 用于识别任务 ID 与类型 |
| `run_id` | string | 单层名，禁含 `/` `\` `..`（路径穿越防护） | 由 zip 内推断 | 目标记录目录名 |
| 分享目标 | — | 当前选中记录 | — | 纯前端截图，无上传 |

## 4. 按钮操作
1. **备份**：点击详情**备份** → 确认框（备份确认）→ 确认 → 浏览器下载 `{run_id}.zip`，提示「备份完成」。
2. **导入**：点击左侧**导入** → 打开抽屉 → 点**上传 zip 包**选择 `.zip` → 上传（带进度）→ 显示结果：
   - **导入成功**：记录已恢复并刷新列表。
   - **导入已存在**：同 `run_id` 记录已存在，不覆盖。
   - **导入失败**：显示错误原因（非 zip / 缺 `run.json` / 无法识别 `run_id` 等）。
   - 点**取消**重置抽屉。
3. **分享**：点击详情**分享** → 确认框（分享确认）→ 确认 → 浏览器下载 `{run_id}.png`，提示「分享完成」。

## 5. 操作步骤（备份 → 迁移 → 导入）
1. 在 Perfs 页选中源记录，点**备份**并确认，得到 `{run_id}.zip`。
2. 将 zip 拷贝到目标机器（与目标机 `~/.benchscope/` 当前目录无关）。
3. 在目标机 Perfs 页点**导入**，**上传 zip 包**选择该文件。
4. 看到「导入成功」后，列表出现该记录，点击即可查看。

## 6. 后台执行逻辑

| 操作 | API | 处理逻辑 |
| --- | --- | --- |
| 备份 | `GET /api/logs/runs/{run_id}/backup` | 收集运行目录全部文件 + 终端日志 `logs/{kind}_{run_id}_*.log`，去重后打包为扁平 zip（`application/zip`）返回 |
| 导入 | `POST /api/logs/runs/import` | 见下方流程 |
| 分享 | 无（纯前端） | `html2canvas` 将详情整页渲染为 PNG（`scale=1.5`，临时展开滚动容器保证长页完整），`toDataURL` 后触发下载 |

**导入流程（`POST /api/logs/runs/import`）**：
1. 读取上传字节，空内容 → 400。
2. 解压到临时目录，**zip-slip 防护**：仅接受扁平文件名（跳过含 `/` `\` `..` 的条目）。
3. 必须存在 `run.json`，否则 400（无法识别任务）。
4. 解析 `kind`（`perf` / `eval`，缺省 `perf`）；推断 `run_id`：优先 `run.json.run_id`，否则从终端日志文件名按正则 `^(perf|eval)_(.+)_\d{6}\d*\.log$` 提取；仍无 → 400。
5. 目标目录 `perfs/<run_id>`（或 `evals/<run_id>`）若已存在 → 返回 `exists`（不覆盖）。
6. 迁移文件：终端日志（`perf_*` / `eval_*` 前缀 `.log`）放入 `logs/`，其余文件放入运行目录。
7. 返回 `ok`，前端刷新列表。

<div class="warning">

**warning**：

导入**不覆盖**已存在的 `run_id`（返回「已存在」）。如需替换，请先在 Perfs 页**删除**该记录再导入。所有路径均经过穿越校验，拒绝越界文件。

</div>

## 7. 常见问题

**问题：导入提示「已存在」？**
目标机已有同 `run_id` 记录。先**删除**旧记录再导入，或改用不同记录。

**问题：导入失败「不是有效的 zip 压缩包」？**
确认上传的是**备份导出的 zip**（扁平结构、含 `run.json`），而非整目录打包或损坏的文件。

**问题：备份出来的 zip 里有哪些文件？**
运行目录内全部文件（`run.json`、`live/*.json`、汇总 / 日志等）+ 对应终端日志 `logs/{kind}_{run_id}_*.log`，均为扁平存放。

**问题：分享图片不完整（被截断）？**
前端会临时展开滚动容器再截图；若仍不全，可缩小浏览器缩放比后重试，或改用**备份**保留完整数据。
