# 并发模式与阈值模式

性能测试提供两种模式，创建向导右上角与任务详情 Cases 面板的模式标签反映当前模式：

- **并发模式（`concurrency`）**：按预设的一组请求数档位依次压测，回答「吞吐与延迟如何随并发变化」；
- **阈值模式（`threshold`）**：从 1 并发开始倍增探测、超阈值后二分，自动找到满足条件的最大并发，回答「这套配置最多能扛多少并发」。

## 1. 功能说明

| 项 | 并发模式 | 阈值模式 |
| --- | --- | --- |
| 核心输入 | 请求数条件（正整数集合） | 每组三项阈值 + Max Requests |
| 执行路径 | 预知：case × 请求数矩阵 | 动态：1, 2, 4, … + 二分 |
| 进度分母 | case 数 × 请求数档位 | case 数（并发点动态探测，不作分母） |
| 结束条件 | 矩阵点位全部跑完 | 每组找到最优并发，或触达上限/超限 |
| 命令预览 | 完整命令列表 | 仅 1 并发首条命令 |
| 最佳标记 | 本地面板阈值 → `Best` | 每组阈值 → `BestPerf` |

## 2. 并发模式

### 2.1 参数

| 参数 | 位置 | 类型/限制 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| 请求数条件 | Step 1 · 条件组 | 正整数集合，自动去重升序；第 1 组必填 | `1,2,4,8,16,32,40,64,128` | 每个值是一档「请求数」（并发档） |
| 输入 / 输出 | Step 1 · 条件组 | 整数；≤0 重置 1024 | 1024 / 1024 | 每组长度组合（可多组） |
| `num-prompts` | Step 2 · 引擎参数 | 整数 ≥0；0 = 跟随并发 | 0 | 每档实际请求数；为 0 时请求数 = 并发档值 |
| `request-rate` | Step 2 · 引擎参数 | `inf` 或正数（req/s） | `inf` | 本轮请求速率；`inf` = 全速 |

### 2.2 执行逻辑

1. 后台 `TaskManager._execute()` 依次遍历 `cases`（每个条件组）。
2. 每个 case 内依次遍历 `concurrency_list`（即请求数条件），每档调用 `_run_one()` 执行一轮压测。
3. 每档完成后 `_record_row()`：`rows` 追加一行、增量写汇总 CSV、持久化、经 WebSocket 广播 `task_result`（表格/曲线实时追加）。
4. `concurrency_list` 中的 `inf` 会映射为 `max_concurrency_search`（默认 256）作为最高并发档执行。

<div class="info">
**执行顺序**：case 按条件组列表顺序执行，组内按请求数列表顺序执行。Cases 面板标签颜色：绿 = 已完成、蓝 = 执行中、灰 = 待执行。
</div>

## 3. 阈值模式

### 3.1 参数

| 参数 | 位置 | 类型/限制 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| TTFT 阈值 | Step 1 · 每组 | 统计量 `mean/median/p99` + 整数 ≥0 | `mean` + 0 | `TTFT-统计量 ≤ 阈值` 才算达标；`0` = 不参与 |
| TPOT 阈值 | Step 1 · 每组 | 同上 | `mean` + 100 | `TPOT-统计量 ≤ 阈值` 才算达标；`0` = 不参与 |
| 输出吞吐阈值 | Step 1 · 每组 | 整数 ≥0（tok/s） | 0 | `output_mean ≥ 阈值` 才算达标（吞吐按**下限**判定）；`0` = 不参与 |
| Max Requests | Step 1 | 整数 ≥ 1 | 4096 | 下一次执行请求数超过它 → 任务强制结束（`Finish`） |
| 搜索上限 | `max_concurrency_search`（后端字段） | 整数 | 4096 | 倍增到上限仍达标 → 上限即最优并发 |

<div class="warning">
**阈值方向注意**：TTFT / TPOT 是延迟指标，按**上界**判定（`TTFT-统计量 > 阈值` / `TPOT-统计量 > 阈值` 即不达标，越低越好）；输出吞吐是吞吐指标，按**下限**判定（`output_mean < 阈值` 即不达标，越高越好）。每组至少一项非 0，否则创建校验不通过。
</div>

### 3.2 扫描逻辑（按条件组独立执行）

`TaskManager._execute_case_threshold()`：

1. **起点**：先跑并发 1；若已不达标 → 1 即最优，该组结束（情景 1）。
2. **倍增探测**：1 → 2 → 4 → 8 …，每测一个并发都追加进 `concurrency_list` 并广播 `task_snapshot`（Cases 面板请求数标签实时增长）。
   - 下一档请求数 > `max_requests` → `forced_finish`：**整个任务结束**，状态显示 **Finish**（非 Done）；
   - 下一档请求数 > 搜索上限且当前仍达标 → 上限即最优并发，该组结束。
3. **二分收敛**：某档 hi 不达标后，在 `(lo, hi]` 内二分，每次测试 `(lo+hi)//2`，直到 `hi - lo == 1`；**lo 为满足全部阈值的最大并发**。
4. **失败容错**：单档执行异常（报错行）不计为阈值不达标，继续向上探测。

```
# 扫描过程示意（TTFT-Mean ≤ 200ms，TPOT-Mean ≤ 100ms）
conc 1 OK → conc 2 OK → conc 4 OK → conc 8 OK
conc 16 FAIL → 二分 (8, 16]
conc 12 FAIL → conc 10 OK → (10, 12]: conc 11 FAIL
→ lo = 10 为该组最优并发（结果表标记 BestPerf）
```

## 4. 两种模式对比

| 维度 | 并发模式 | 阈值模式 |
| --- | --- | --- |
| 进度条（Perf 面板） | 完成数/总数，总数 = case × 请求数 | 完成数/总数，总数 = case 数 |
| Cases 面板请求数标签 | 显示全部请求数（升序） | 只显示已测请求数（未执行显示 `Pending`） |
| 组标题/标签附加信息 | 无阈值文本 | 显示该组阈值条件（如 `TTFT-Mean ≤ 200ms · TPOT-Mean ≤ 100ms`） |
| 任务结束状态 | `done` | `done`（到上限）或 `Finish`（强制结束） |
| 结果表标记 | `Best`（本地面板阈值） | `BestPerf`（每组阈值） |

## 5. 常见问题

**问题：阈值模式里「下一次执行请求数」指什么？**
指下一探测档的并发值（`num-prompts=0` 时请求数 = 并发数）。它超过 `max_requests` 时任务立即结束并标记 `Finish`，防止倍增探测消耗过多请求。

**问题：不同长度组合想用不同阈值，可以吗？**
可以。阈值按条件组（`case_id`）独立保存，每组的扫描、Cases 面板展示与 BestPerf 标记互不影响。

**问题：倍增探测到搜索上限仍达标，结果是什么？**
搜索上限（默认 4096）即为最优并发并标记 BestPerf；如需继续探测，可在后端字段 `max_concurrency_search` 调大上限。

**问题：某一档执行失败了会影响扫描吗？**
不会。失败行以 `Failed` 记入结果表，但不计为阈值不达标，探测继续向上进行。
