# v1.1.1 Release Notes

**Release date**: 2026-09-05
**Change type**: patch (pushed to PyPI with special handling per user instruction)

## Version Overview

v1.1.1 is a **fix release** following v1.1.0 (performance real-time panel / single-request snapshot / Dashboard Overview rework / Sessions experience), focusing on installer integrity and configuration robustness: after `pip install`, every Settings panel has content, historical Providers can be edited normally, and images on the PyPI page render correctly.

## Update Contents

### Fix: Empty Settings content in the installed package

The release package now ships `benchscope/configs/*.yaml` (9 configuration files such as models / datasets / benchs) and the built-in skills directory — after `pip install`, **every panel of Settings — Models / Datasets / Bench Engines / Skills — has entries** (no longer dependent on the source directory).

### Fix: Missing Provider id

Legacy Providers (such as the old "Default", migrated from an old configuration containing only the `api` field) may be missing the `id` field, which prevented the performance task-creation flow from selecting that Provider and caused Settings editing to report "Unknown Provider: undefined". Now, when the configuration is loaded, **missing stable ids are automatically backfilled** (generated from the name slug, e.g. Default → `provider_default`, with a numeric suffix appended on conflict to guarantee uniqueness) and persisted in sync; when `active_provider` is missing / invalid, it falls back to the first valid id.

### Fix: PyPI image rendering

The main screenshot in the README was replaced with `benchscope-performance.png`; the image references for the logo and the main screenshot were changed to **GitHub raw absolute URLs** (`https://raw.githubusercontent.com/...`) so that the PyPI page can also render images correctly (previously the relative paths could not be resolved on PyPI).

### Skills moved into the package

The built-in skills directory was moved from the repository root `skills/` into the package at `benchscope/skills/` and is distributed as package-data; the path resolution in `api_skills` was updated accordingly, so **the paths are consistent between development and after installation** (Settings → Skills behaves identically in both environments).

## Verification Points

- Rebuilt wheel / sdist: both contain `benchscope/configs/*.yaml` (9 files) and `benchscope/skills/**/*` (30 files).
- `GET /api/config/model-catalog` = 2 groups, `GET /api/config/datasets` = 12, `GET /api/benchs` = 5 engines (benchscope / vllm-0.23 / sglang-0.5.10 / native-hf / mock), `GET /api/skills` = 3 skills.
- Constructed an old settings.json containing a Default without an id → after loading, `list_providers()` returns `id=provider_default` and it has been persisted; editing succeeds.

## Upgrade Notes

- Upgrading from v1.1.0: just run `pip install --upgrade benchscope`, no data migration needed; if you manually modified the `skills/` directory, be aware that it has been moved into the package at `benchscope/skills/`.
- The id backfill for historical Providers is completed automatically on **first startup**, after which they can be edited normally in Settings.
