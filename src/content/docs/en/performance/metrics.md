# Performance Core Metrics

This page is the **complete reference** for performance-testing metrics: it covers the core metrics output at each concurrency point, the per-run request statistics, the threshold-mode decision results, and the column definitions in the exported files. When you meet a metric name in the other performance pages ([Concurrency Testing](/en/docs/performance/concurrency/), [Threshold Testing](/en/docs/performance/threshold/)), look up its meaning here.

## Core Metrics (One Set per Concurrency Point)

The stress test uses **concurrency** as the horizontal axis; each concurrency point outputs a set of metrics. Latency metrics provide three statistics — `mean` / `median` / `p99` — while throughput metrics provide `mean`.

| Metric | Key | Unit | Statistic | Meaning |
| --- | --- | --- | --- | --- |
| First-token latency TTFT | `ttft_mean` / `ttft_median` / `ttft_p99` | ms | mean / median / p99 | Time from sending the request to receiving the first generated token; reflects the first-token response speed perceived by the user; **lower is better**. |
| Per-output-token latency TPOT | `tpot_mean` / `tpot_median` / `tpot_p99` | ms | mean / median / p99 | Average time to generate each output token; determines the sustained smoothness of streaming output; **lower is better**. |
| Token interval latency ITL | `itl_mean` / `itl_median` / `itl_p99` | ms | mean / median / p99 | Interval time between two adjacent output tokens; characterizes the jitter and stutter of streaming output; **lower is better**. |
| Output throughput | `output_mean` | tok/s | mean | The rate at which the server generates output tokens (total output tokens / stress-test duration); **higher is better**. |
| Peak output throughput | `peakoutput_mean` | tok/s | mean | The peak output-token rate observed within the stress-test window (provided by vLLM; recorded as N/A when the engine does not provide the value). |
| Total token throughput | `total_mean` | tok/s | mean | Total processing rate of input + output tokens (total tokens / stress-test duration); measures the overall processing capacity of the service; **higher is better**. |
| Request throughput | `req_per_s` | req/s | mean | Number of requests completed per second (successful requests / stress-test duration); measures the request rate the service can carry; **higher is better**. |
| Single-user throughput | `single_user` | tok/s | Derived value | The generation rate a single user can obtain, derived as `1000 / TPOT(mean)`, approximating the speed of one person generating continuously. |

### Statistics Explained

| Statistic | Meaning | Usage Advice |
| --- | --- | --- |
| `mean` | Mean | Reflects the overall level; use for routine comparison. |
| `median` | Median | Not sensitive to extreme values; when the distribution is skewed, it better represents the typical experience. |
| `p99` | 99th percentile | Characterizes tail latency; for strict SLA scenarios (e.g. online chat), it is recommended to take p99 as the standard. |

**Info:**

Metric availability for third-party engines (vLLM / SGLang native output): **available → numeric value (blue); unavailable → N/A (dark gray); missing → gray dash**. For example, SGLang's native output does not include peak output throughput, so that column shows N/A, which is normal.

## Request Statistics (One Set per Run)

| Metric | Key | Unit | Meaning |
| --- | --- | --- | --- |
| Successful requests | `successful_requests` | count | Number of requests that completed successfully (received a full response) in the stress test. |
| Failed requests | `failed_requests` | count | Number of requests that failed (timeout / error / incomplete) in the stress test; should be 0 in a healthy stress test. |
| Benchmark duration | `benchmark_duration` | s | Wall-clock duration of the whole stress-test round (from the first request sent to all requests finished). |
| Total input tokens | `total_input_tokens` | tokens | Total amount of all input tokens sent in this stress-test round. |
| Total output tokens | `total_generated_tokens` | tokens | Total amount of all output tokens generated by the server in this stress-test round. |
| Peak concurrency | `peak_concurrent` | count | Peak number of in-flight requests at the same time during the stress test. |

## Threshold Mode Results

| Metric | Key | Unit | Meaning |
| --- | --- | --- | --- |
| Best concurrency | `best_concurrency` | count | The maximum concurrency in threshold mode that satisfies **all** threshold conditions (TTFT / TPOT / output throughput); when the search upper limit is reached and still satisfied, the upper limit is taken. |

See [Threshold Testing](/en/docs/performance/threshold/) for the threshold conditions and evaluation statistics (`mean` / `median` / `p99`).

## Single-Run Snapshot Contract

Every concurrency point (including single-request snapshots) outputs the following **11 metrics** uniformly, keeping the structure consistent across engines and runs:

`output_mean` · `peakoutput_mean` · `total_mean` · `ttft_mean` · `tpot_mean` · `itl_mean` · `ttft_p99` · `tpot_p99` · `itl_p99` · `req_per_s` · `single_user`

When an engine does not support a metric, it is filled with N/A; the keys remain unchanged.

### Excel Export (benchmark-*.xlsx)

The file contains a **Mean** worksheet and a **P99** worksheet; column definitions are as follows:

| Column | Meaning |
| --- | --- |
| GPU | GPU information of the deployment. |
| Model | Name of the model under test. |
| Precision | Model precision (e.g. FP16 / INT8). |
| Inference Framework | Inference framework used by the service under test. |
| Input Length / Output Length | Input / output token lengths of the case. |
| Concurrency | The concurrency point of this row. |
| Output | Output throughput (tok/s). |
| Peak Output | Peak output throughput (tok/s). |
| Total | Total token throughput (tok/s). |
| TTFT / ITL / TPOT | Latency metrics (ms); the P99 sheet holds the corresponding percentile values. |
| Single User | Single-user throughput (tok/s). |

The best row (TPOT closest to, and below, the threshold) is highlighted in the table.

### CSV Summary

The summary CSV is grouped by **test case**; each group has a "Test Conditions" header row (case label / input / output / deployment GPU) and data rows: Concurrency, Output, Peak Output, Total, TTFT, TPOT, ITL. Files are provided in two sets — mean and P99.

## FAQ

**Question: Why does peak output throughput show N/A?**
Only some engines (vLLM) provide this metric; SGLang's native output does not include it, so it shows as N/A without affecting other metrics.

**Question: What is the difference between TPOT and ITL?**
TPOT is the "average time to generate each output token", covering the overall rhythm after the first token; ITL is the "actual gap between two adjacent tokens", closer to token-by-token jitter. When the two are close, output is steady; when ITL is noticeably larger than TPOT, there is stuttering.

**Question: How is single-user throughput calculated?**
It is derived as `1000 / TPOT(mean)`, approximating the token rate of a single user generating continuously, making it easier to understand the single-user experience from a throughput perspective.
